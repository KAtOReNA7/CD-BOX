# CD-BOX Product Spec

CD-BOX 是供一名收藏者使用的本机发行资料与收藏管理 WebUI。它管理艺人、官方发行作品、嵌套版本、来源、封面、导入历史、研究任务和收藏状态。产品不面向公众，不提供注册、邀请、团队、角色或用户管理。

本文是冻结的目标产品规范。历史实现、当前 fixture 和阶段性测试只能说明进度，不能缩小本文范围；真实完成度以 `docs/PROGRESS.md` 为准。

## 产品与运行边界

- Next.js App Router、TypeScript、React、Tailwind CSS、shadcn/ui、Prisma 和 PostgreSQL。
- Windows 本机、单 owner；生产与开发入口都只监听 `127.0.0.1:3000`。
- `LOCAL_OWNER_MODE=true` 建立本机 owner；页面、Route Handler 和 Server Action 仍执行服务器端 owner、Host 和 Origin 校验。
- 不使用 Vercel、云托管、云数据库、外部 OAuth、反向代理、对象存储或新的付费服务。
- 真实秘密只保存在 Git 忽略且 ACL 受限的 `.env.local`，不得出现在命令参数、文档、日志、测试输出或 Git。
- 本机 PostgreSQL 是唯一运行数据库；结构变更使用已提交 migration 和 `prisma migrate deploy`，禁止以 `prisma db push` 代替发布迁移。

## 页面与主要工作流

- `/`
- `/dashboard`
- `/artists/new`
- `/artists/[id]`
- `/releases/[id]`
- `/import`
- `/ai-search`
- `/settings`

Owner 可以创建艺人库、搜索完整官方发行、查看作品与版本、选择已核验资料导入、维护收藏状态、批量编辑、导入或导出 Excel、备份和恢复本机数据库。

## 完整官方发行范围

目标是某艺人关联的**全部官方发行**，不限于实体 CD、单曲或原创专辑。

包含的发行类别至少包括：

- 单曲；
- EP／迷你专辑；
- 原创专辑；
- 精选；
- Live；
- Remix；
- Soundtrack；
- Tribute；
- 普通合集；
- Box Set；
- 官方影像；
- 其他官方发行。

介质范围包括全部官方音频和视频介质，包括但不限于数字发行、黑胶、卡带、CD、SACD、DVD、Blu-ray 和其他官方载体。官方 promo、非卖品、自费发行、会场限定及歌迷会发行均在范围内。

以下内容不收录，并必须带来源、阶段和原因进入显式排除台账：

- 非官方发行或盗版；
- 卖家自行拼装、未获官方发布身份的套装；
- 仅因曲目出现而被误判成艺人独立发行的商品；
- 无法建立官方身份且证据不足的候选。证据不足不是永久否定，候选应保持待核验。

合作、共同名义、客演、化名、早期名义和多语言市场发行必须保留真实 credit 和关系，不能只按一个英文艺人名过滤。

## 作品与版本数据模型

### 顶层作品

顶层按**发行作品**计数。一个作品代表一次可辨识的官方发行计划或内容边界，例如一张专辑、一个单曲作品、一套 Box Set 或一项官方影像发行。

- 同一作品的地区版、介质版、初回版、通常版、再版、重制版、豪华版和其他商品版本不得重复成为顶层作品。
- 名称不同的作品不能仅因发行日期相同而合并。
- 普通合集、精选、Tribute、Soundtrack 和 Box Set 本身可以是官方作品；其包含其他曲目或作品的关系另行表达，不能用碟数或曲目数冒充顶层作品数。
- 稳定官方 ID、来源实体 ID 和可审计的跨来源映射优先于标题归一化。

### 嵌套版本

每个作品下保存零到多个版本。版本至少可表达：

- 原始标题与本地化标题；
- 艺人 credit；
- 地区；
- 介质和格式；
- 版本／商品类型；
- 品番、条码及来源实体 ID；
- 版本发行日期；
- 官方、promo、非卖品、会场、歌迷会等发行属性；
- 版本级来源和封面状态。

`originalReleaseDate` 表示作品首次正式发行日期；具体版本日期必须单独保存，不能用再版、CD 化或套装日期覆盖作品日期。无法安全归并的版本保持待核验，不能猜测合并。

## 多语言名称与检索

- 保存艺人、作品和版本的来源原文，不得统一翻译成英文后丢弃日文、中文或其他文字。
- 艺人主名称、受控别名、旧名、艺名、罗马字、简繁体和来源特定 credit 分开保存并注明来源。
- 搜索可用任一受控别名命中同一艺人；结果优先显示用户可读的原文名称并同时提供其他文字别名。
- 标题跨文字等值只有在稳定 ID、艺人、日期、品番或其他证据共同支持时才能归并。翻译相似或日期相同不能单独证明同一作品。
- 确定性的 Unicode、标点、宽窄字符和大小写归一化由程序处理；仍有实质语义歧义时才交给 AI。

## 发行研究台账与状态

研究必须分别报告“权威范围内有多少作品”“每个作品有多少版本”“哪些资料已核验”“哪些仍待证据”和“封面状态”，不得只展示少量最终结果。

- **`canonicalWorks`**：由艺人官网、厂牌目录、国家书目或其他版本化权威来源确认的官方作品总账。
- **`pendingEvidence`**：作品或版本仍缺官方身份、版本绑定或冲突裁决所需证据。它继续计入目录守恒，但不能伪装成已核验。
- **`VERIFIED`**：发行作品及需要展示／导入的版本已通过资料证据、确定性规则与必要的 AI 语义复核。
- **显式排除**：已证明不属于目标范围，具有非空 `stage`、`reasonCode` 和来源。

目录守恒要求：

```text
权威官方作品 = VERIFIED + pendingEvidence + 有证据的显式排除／范围裁决
```

来源暂时不可用、未命中或封面缺失不能减少左侧总账。

## 证据与 AI 边界

### 证据

- 官方作品身份优先来自艺人、厂牌、发行方、国家书目或其他可审计权威来源。
- 一条与目标作品或版本精确绑定的一级证据即可确认它所直接支持的事实。找不到一级证据的老作品，必须由两个相互独立的可靠来源共同确认，且至少一个来源提供品番、条码、曲目、介质、版本日期等实体级信息。
- 版本证据必须绑定具体作品和版本实体；列表页、搜索摘要、年份相同或封面相似不能单独证明版本。
- 不要求每条记录同时命中 MusicBrainz、NDL、Discogs 和 GPT，但每个 `VERIFIED` 结论必须有足以支持其字段的来源链。
- 正规零售或二手市场可以在官方身份已独立成立后补充封面或版本线索，不能单独证明发行是官方的。
- 非官方、卖家套装和来源冲突必须失败关闭；来源短暂故障保持未决，不得转成错误排除。

### AI

所有文本模型调用统一经过 `src/lib/ai/client.ts`，使用本机配置的 OpenAI-compatible 中转站及已验证的 Chat Completions 能力，不经过额外 AI 路由服务。

- 艺人、标题、类别、介质、地区、品番、日期、稳定 ID 和来源绑定等确定性判断由程序完成。
- 所有准备展示或导入的联网研究候选都必须经过一次批量 AI 证据审核，再由确定性规则复核；无歧义候选可以使用紧凑的批量审核，但不能未经 AI 审核直接反馈给用户。
- AI 只比较已提供的证据，裁决跨文字标题等值、艺人别名归属或来源间实质冲突；它的结论不是新的外部证据。
- AI 不能联网浏览、凭记忆补事实、创造来源、修改确定性字段或绕过证据门禁。
- 模型、鉴权、额度、超时或结构错误使相关候选保持 `pendingEvidence`，不得丢弃已有公共证据或伪装成功。
- 结构修复必须有界，禁止递归二分形成请求树。

## VERIFIED 与封面解耦

封面不是发行官方性或资料正确性的证明。发行证据通过后即可为 `VERIFIED`，即使尚未找到封面。

每个可展示版本具有独立封面状态：

- **`EDITION`**：图片与具体版本实体绑定；
- **`WORK`**：图片只安全绑定到作品，不宣称代表当前版本；
- **`MISSING`**：尚无通过校验的正确图片。

`MISSING` 不阻塞 `VERIFIED`、展示、选择、收藏操作、导出或导入。界面必须清楚显示缺图状态，后续补图不得改写作品或版本证据结论。

封面要求：

- 先验证图片是否适用于目标作品／版本，再考虑速度和来源优先级。
- URL 必须使用允许的 HTTPS 来源，并通过受控重定向、状态、真实图片签名、MIME、尺寸和响应体上限校验。
- 禁止使用错误图片、生成图或无来源图片填空。
- 同一图片可以在来源明确证明共享包装时复用，但必须表达共享层级，不能谎称为不同版本的独立封面。

### 动态快速来源

封面候选可来自官方来源、Cover Art Archive／Discogs、正规零售和二手市场。提供商顺序不是固定产品语义：

1. 先按目标版本、地区、介质和来源约束过滤不适用候选；
2. 在正确候选中按近期成功率、响应速度和熔断状态动态排序；
3. 连续故障的来源快速熔断，避免对每个候选重复等待；
4. 后台恢复时从检查点继续，不重新请求已经验证的图片。

不得绕过登录、验证码、付费墙、反自动化保护或服务条款；不得为补图新增付费依赖。

单次图片请求最多等待 8 秒并最多重试一次；单作品前台补图最多 20 秒，同一来源连续失败 3 次立即熔断。选定封面下载到本机并保存来源页面、原图地址、内容哈希、匹配层级和获取时间，不依赖外部热链。永久封面及用户上传的 JPG、PNG、WebP 保存在 PostgreSQL，以便随 `.dump` 备份恢复；`var/` 只保存可以重新生成的缩略图缓存。用户提供的封面必须标记来源且不得被自动回填覆盖。

## 艺人库与收藏

艺人页以作品为顶层行，并可展开版本。至少显示：

1. 收藏状态；
2. 发行类别；
3. 原文标题及别名；
4. 作品首次发行日期；
5. 版本数量和主要介质；
6. 证据状态；
7. 封面状态；
8. 来源数量；
9. 备注。

支持：

- 收藏状态 `OWNED`、`NOT_OWNED`、`WANTED`、`EXCLUDED`、`PENDING_REVIEW`；
- 1–5 优先级；
- 作品与版本详情、来源增删及人工备注；
- 按类别、介质、地区、证据、封面和收藏状态筛选；
- 批量操作、缺口视图、统计和 Excel 导出。

人工编辑证据字段后必须重新核验；人工收藏状态和备注不得被后续研究覆盖。

## 导入、重复检测与幂等性

`/import` 支持 `.xlsx` 上传、只读预览、重复检测和明确确认后事务写入。旧工作表 `A_OriginalAlbumOriginalCD`、`B_SingleOriginalCD`、`C_BestLiveRemix` 及等价日文表名保持向后兼容，但目标导入模型必须覆盖全部官方类别和介质。

导入映射到作品、嵌套版本、来源和独立封面状态，而不是把每个 Excel 行无条件创建为顶层发行。

幂等要求：

- 稳定作品／来源 ID 优先用于匹配作品；
- 版本按作品、地区、介质、品番、版本日期和版本属性组成的稳定身份匹配；
- 来源 URL 在所属实体内去重；
- 同一预览或同一已核验候选重复确认，不新增重复作品、版本、来源或收藏关联；
- 更新保留人工备注、收藏状态和未被明确替换的数据；
- 预览不写库，确认阶段使用事务；失败时不得产生半导入。

AI 结果永不自动写入正式库。Owner 只能选择 `VERIFIED` 候选并确认导入；导入 API 再次校验 owner、候选 ID、证据状态和目标艺人。封面为 `MISSING` 仍允许导入。

## 粘贴资料整理

Owner 可以粘贴官网、厂牌、零售商、数据库、CSV 或表格文本。该模式不联网，也不得声称执行过搜索。

- 来源只能来自粘贴文本中的显式 URL 或用户单独输入的 URL。
- 封面只保留用户显式提供且通过安全校验的 URL。
- 缺失字段保持 `null`，不得猜品番、日期、封面或来源。
- 与联网研究复用同一作品／版本、证据、封面和幂等导入模型。
- 粘贴资料不能仅凭用户文本自动获得 `VERIFIED`，仍须满足证据边界。

## 任务预算、进度与检查点

- 一次完整单艺人搜索正常目标为 3–8 分钟，硬上限 15 分钟。
- AI 每批约 20 个真正需要语义裁决的候选，并按提示体积向下调整。
- 单次 AI 请求硬超时 75 秒；首次失败后最多 2 次有界修复；连续 2 次失败立即熔断。
- 单艺人全部 AI 阶段硬上限 10 分钟。
- 前台封面补全硬上限 3 分钟；到限返回现有发行和 `EDITION`／`WORK`／`MISSING` 状态，后续后台恢复。
- 每完成一个来源页、AI 批次或封面批次，立即原子保存 Git 忽略的检查点。检查点绑定输入、策略／fixture 哈希和版本。
- 恢复只处理缺失部分，不重新下载或裁决已通过且输入未变的部分。
- 长任务持续显示阶段、已完成／总数、已用时间、剩余硬预算和最近检查点。
- 到达硬上限或连续缺少预期进度时必须保存现场、优雅停止并返回可诊断状态，禁止扩大超时、无限重试或静默等待。
- 浏览器关闭不停止服务器任务。程序或电脑异常退出后，下次本机启动只允许从最近有效检查点自动恢复一次；用户主动暂停或取消的任务不得自动恢复，同一错误再次出现时必须停止并展示原因。
- 暂停停止发起新请求并保留任务；取消采用优雅终止。恢复继续使用同一任务和输入快照，不能创建新任务绕过预算。

## 持久化

- `AiSearchTask` 保存任务状态、预算、阶段、心跳和检查点索引。
- `rawResult` 保存公共证据、模型响应快照、来源统计和脱敏错误。
- `parsedResult` 保存完整作品／版本台账、证据状态和独立封面状态。
- 公共响应、证据判断和封面内容按稳定键持久缓存并遵守来源许可、TTL 和失效规则。
- 失败任务保留可操作且脱敏的错误，不记录 API 密钥、数据库密码或完整连接串。

## 历史库迁移

- 结构变化提交 Prisma migration，并在写入前备份。
- 旧的平面 `Release`、`ORIGINAL_CD` 和 `PENDING_COVER` 数据必须通过版本化迁移映射到作品、版本、证据和独立封面状态。
- 迁移先只读聚合全部不兼容，再应用；不得在真实联网验收中逐条发现并加入艺人姓名特例。
- 迁移重复执行必须幂等，保留人工备注、收藏状态、来源和可证明正确的现有资料。

## 无新增付费依赖

- 优先使用项目已有依赖和 Codex 已安装能力。
- 新工具必须可本机运行、开源或免订阅，且不要求信用卡。
- 不引入自动续费、按请求收费的搜索服务、云数据库或托管平台。
- Codex 的浏览器或计算机控制只用于开发和验收，不能成为 CD-BOX 运行时后端。

## 验收策略

### 完整验收艺人

完整产品验收必须覆盖：

- 中山美穂；
- 松田聖子；
- 中森明菜；
- 山口百恵；
- 坂本龍一；
- 邓丽君；
- 王菲；
- The Beatles。

八位艺人共同覆盖大型旧目录、全类别与多介质、官方影像、Soundtrack、跨文字、跨市场和西方目录。Fixture 可以包含艺人专属事实，但核心算法不得依赖艺人姓名特例。

### 分层验收

1. **离线回放**：不访问网络、不调用 AI，跑完全部选定艺人并一次聚合所有不守恒、误合并、重复、证据、封面状态和幂等导入问题。
2. **公共资料预检**：只访问允许的公共来源，不调用 GPT；遵守限速、预算和熔断，按来源页和封面批次保存检查点。单来源故障记为未决，不删除作品。
3. **本机产品验收**：在 `127.0.0.1:3000` 验证 owner 边界、作品／版本 UI、创建、筛选、选择、幂等导入、导出、备份、恢复、优雅停止和重启。
4. **真实 AI 最终套件**：只有离线、公共、本机构建、migration 和运行验收通过后才执行。同一提交从头最多运行一次；失败后只从未完成检查点恢复，不重复消耗已完成艺人。

当前四艺人 `ORIGINAL_CD` 套件只能作为迁移期回归测试，不能替代八艺人全官方发行验收。

### 质量阈值

- 八位艺人的版本化权威官方作品守恒率：100%；
- 所有候选均有明确状态；无阶段／无原因静默丢弃：0；
- Fixture 中同作品被错误拆成多个顶层作品：0；
- Fixture 中不同作品被错误合并：0；
- `VERIFIED` 项具有支持其官方身份和关键字段的证据链：100%；
