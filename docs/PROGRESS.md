## 已冻结的目标方向

- Windows 本机、单 owner、仅 `http://127.0.0.1:3000`；PostgreSQL 16 是唯一运行数据库。
- 不使用 Vercel、云数据库、外部登录、反向代理或新的付费服务。
- 产品范围是八位验收艺人的全部官方发行，不限于 `ORIGINAL_CD`、单曲或原创专辑；覆盖全部官方音视频介质、promo、非卖品、自费、会场和歌迷会发行。
- 顶层按作品，地区、介质、初回、再版、重制和其他商品版本嵌套保存。
- `VERIFIED` 由资料证据、确定性规则和必要的 AI 语义复核决定；封面独立为 `EDITION`、`WORK` 或 `MISSING`，缺图不阻塞展示、选择或导入。
- 封面来源在正确性过滤后，按近期速度、成功率和熔断状态动态排序；零售和二手市场只能补图或补充线索，不能单独证明官方身份。
- 单艺人完整搜索硬上限 15 分钟、AI 阶段 10 分钟、单次 AI 75 秒、前台封面 3 分钟；每个来源页、AI 批次和封面批次立即保存检查点。
- 完整验收艺人为：中山美穂、松田聖子、中森明菜、山口百恵、坂本龍一、邓丽君、王菲、The Beatles。

详细目标和质量阈值以 `docs/PRODUCT_SPEC.md` 为准。

## 长时间停滞的已确认教训

本轮历史执行暴露了流程问题，而不是需要继续放宽等待时间：

- 一次真实 AI 套件从 09:46 运行至 12:13；AI 结构错误的递归拆批和过长单次超时会放大调用。
- 一次封面重试从 12:44 运行至 13:27，共尝试 62 条、找到 0 条；公共来源整体故障时缺少足够早的来源级熔断。
- 公共预检先后出现 v1–v4 重跑；当前检查点不能复用失败艺人的来源页和阶段成果。
- 真实 AI runner 在整位艺人结束前缺少足够的命令行可见进度，造成“仍在运行但没有可审计产出”。

这些执行已停止。后续任何阶段达到硬上限，或连续缺少约定心跳／检查点，必须优雅终止并转为更小的离线诊断，禁止继续运行数小时。

## 收敛实施顺序

1. **通用模型与 migration**：建立作品、嵌套版本、全类别／介质、发行属性和独立封面状态；先只读聚合旧数据差异，再迁移，禁止新增姓名特例。
2. **证据与搜索编排**：将官方身份、版本证据、AI 语义裁决和封面完全解耦；实现 15／10／3 分钟预算、75 秒请求、两次修复、来源级熔断和批次检查点。
3. **动态封面与 UI**：实现适用性过滤、动态健康排序、`EDITION`／`WORK`／`MISSING` 展示和缺图可选择／导入。
4. **幂等导入**：按作品和版本稳定身份重做重复检测；验证重复确认不会产生任何新增重复实体。
5. **八艺人 fixture**：在数据层扩展中山美穂、松田聖子、中森明菜、山口百恵、坂本龍一、邓丽君、王菲和 The Beatles 的全官方发行基准，不把事实写进核心算法。
6. **分层验收**：先定向单元测试和 `npm run check`／`npm run build`，再八艺人离线回放；之后只运行一次可恢复的公共预检、本机验收，最后同一提交最多一次真实 AI 完整套件。
7. **发布审计**：验证 migration、备份／恢复、回环安全、README／AGENTS／本机部署文档、敏感信息、分支和远端祖先关系后再提交推送。

每一步必须产生可审计差异、通过的有界测试或持久检查点。没有产出时立即停止该步并诊断，不能跳到下一次完整真实测试。
